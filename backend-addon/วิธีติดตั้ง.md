# วิธีติดตั้งระบบแจ้งเตือนมือถือ (สำหรับผู้สร้างเว็บ OEE)

ไฟล์ `oee-push.js` เป็นส่วนเสริมแยกไฟล์ **ไม่แก้โค้ดเดิม** เพิ่มแค่ ~5 บรรทัดใน `worker.js`
ใช้ Web Crypto ของ Cloudflare ล้วน ไม่ต้องติดตั้ง npm package และใช้ D1 ตัวเดิม (สร้างตารางใหม่ของตัวเอง 2 ตาราง: `push_subs`, `push_state`)

## สิ่งที่ได้
| เหตุการณ์ | แจ้งเตือน | เมื่อไร |
|---|---|---|
| มีเครื่องแจ้งเสียใหม่ (`maintenance-alerts`) | 🔴 เครื่อง MP37 แจ้งเสีย | ทันทีที่บันทึก |
| อะไหล่เพิ่งต่ำกว่า Min (`spare-parts`) | 📦 อะไหล่ต่ำกว่า Min | ทันทีที่บันทึก |
| อะไหล่แม่พิมพ์เพิ่งต่ำกว่า Min (`mold-stock-parts`) | 🛠 อะไหล่แม่พิมพ์ต่ำกว่า Min | ทันทีที่บันทึก |
| PPM ใกล้ถึง / เกินกำหนด (`ppm-plans`) | 🗓 สรุป PPM | ทุกเช้า 07:30 |

- แจ้งเฉพาะ "เรื่องใหม่" ไม่แจ้งซ้ำ และครั้งแรกหลังติดตั้งจะไม่แจ้งของเก่าที่ค้างอยู่
- กดที่แจ้งเตือนแล้วเปิดหน้าที่เกี่ยวข้องในแอป OEE

---

## ขั้นที่ 1: สร้างกุญแจแจ้งเตือน (ครั้งเดียว)
ในคอมที่มี Node.js รัน:
```
npx web-push generate-vapid-keys
```
จะได้ `Public Key` กับ `Private Key` เก็บไว้

## ขั้นที่ 2: ตั้งค่าใน Cloudflare
Cloudflare → Workers & Pages → เลือก Worker ของ OEE → **Settings → Variables and Secrets** → Add

| ชื่อ | ชนิด | ค่า |
|---|---|---|
| `VAPID_PUBLIC_KEY` | Secret | Public Key จากขั้นที่ 1 |
| `VAPID_PRIVATE_KEY` | Secret | Private Key จากขั้นที่ 1 |
| `VAPID_SUBJECT` | Text | `mailto:อีเมลผู้ดูแล` |
| `PUSH_ADMIN_KEY` | Secret | รหัสยาวๆ ตั้งเอง (ใช้สั่งส่งแจ้งเตือนเอง) |
| `PUSH_ALLOWED_ORIGIN` | Text | `https://jotbot196-design.github.io` |

ถ้า D1 binding **ไม่ได้ชื่อ `DB`** ให้เพิ่ม `PUSH_DB_BINDING` (Text) = ชื่อ binding นั้น

## ขั้นที่ 3: เพิ่มโค้ดใน worker.js
วางไฟล์ `oee-push.js` ไว้ข้าง `worker.js` แล้วเพิ่ม 4 จุด (ส่วนที่มี `// ← เพิ่ม`):

```js
import { handlePush, onKvWrite, pushCron } from './oee-push.js';   // ← เพิ่ม (1)

export default {
  async fetch(request, env, ctx) {
    const pushRes = await handlePush(request, env);                 // ← เพิ่ม (2)
    if (pushRes) return pushRes;                                    //    (ต้องอยู่บนสุด ก่อน route อื่น)

    // ... โค้ดเดิมทั้งหมด ...

    // ในส่วนที่จัดการ PUT /api/kv — หลังบันทึกลง D1 สำเร็จแล้ว:
    //   path  = ค่า ?path=... ของ request
    //   value = ข้อมูลที่เพิ่งบันทึก (body ที่ parse JSON แล้ว)
    ctx.waitUntil(onKvWrite(env, path, value));                     // ← เพิ่ม (3)

    // ... โค้ดเดิม ...
  },

  async scheduled(event, env, ctx) {                                // ← เพิ่ม (4)
    // readKvValue = ฟังก์ชันเดิมที่อ่านค่าของ path จาก D1 (ค่าเดียวกับที่ GET /api/kv ตอบใน .value)
    ctx.waitUntil(pushCron(env, path => readKvValue(env, path)));
  }
};
```

> ถ้ามี `scheduled()` อยู่แล้ว ให้เพิ่มบรรทัด `ctx.waitUntil(pushCron(...))` เข้าไปในของเดิม
> ถ้าโค้ดเดิมยังไม่มีฟังก์ชันอ่านค่า ให้ใช้คำสั่ง SELECT เดียวกับที่ GET /api/kv ใช้

## ขั้นที่ 4: ตั้งเวลาเช็ค PPM ทุกเช้า
- ใช้ `wrangler.toml`:
  ```toml
  [triggers]
  crons = ["30 0 * * *"]   # 07:30 น. เวลาไทย
  ```
- หรือใน Dashboard: Worker → **Settings → Trigger Events → Add → Cron Triggers** → `30 0 * * *`

## ขั้นที่ 5: Deploy แล้วเช็ค
1. เปิด `https://oee.sasatornua.workers.dev/api/push/public-key` ต้องเห็น `{"publicKey":"B..."}`
2. ส่ง **Public Key** และยืนยันว่า deploy แล้ว ให้ผู้ดูแลแอป เพื่อเปิดปุ่ม "เปิดการแจ้งเตือน" ในแอป

## ทดสอบส่งแจ้งเตือนเอง (หลังมีคนกดอนุญาตแล้ว)
```
curl -X POST https://oee.sasatornua.workers.dev/api/push/send \
  -H "Authorization: Bearer <PUSH_ADMIN_KEY>" -H "Content-Type: application/json" \
  -d '{"title":"ทดสอบ","body":"ระบบแจ้งเตือนใช้งานได้","page":"maintenance"}'
```
ผลลัพธ์ เช่น `{"total":3,"sent":3,"removed":0,"failed":0}`
ดูจำนวนเครื่องที่รับแจ้งเตือน: `GET /api/push/stats`

## API ที่เพิ่ม (ทั้งหมดอยู่ใต้ `/api/push/` ไม่ชนกับของเดิม)
| Method | Path | ใช้ทำอะไร | สิทธิ์ |
|---|---|---|---|
| GET | `/api/push/public-key` | ให้แอปขอกุญแจสาธารณะ | ทุกคน |
| POST | `/api/push/subscribe` | มือถือลงทะเบียนรับแจ้งเตือน | ทุกคน |
| POST | `/api/push/unsubscribe` | ยกเลิกรับ | ทุกคน |
| POST | `/api/push/send` | สั่งส่งแจ้งเตือนเอง | ต้องมี `PUSH_ADMIN_KEY` |
| GET | `/api/push/stats` | จำนวนเครื่องที่ลงทะเบียน | ทุกคน |

## ความปลอดภัย
- `onKvWrite` และ `pushCron` **อ่านอย่างเดียว** ไม่แก้ข้อมูล OEE เดิม
- ตารางที่สร้างเพิ่มเก็บแค่ "ที่อยู่รับแจ้งเตือน" ของมือถือ (ไม่มีชื่อ / เบอร์ / ข้อมูลส่วนตัว)
- ถ้า `oee-push.js` เกิดข้อผิดพลาด จะไม่ทำให้การบันทึกข้อมูลเดิมล้ม (ดักไว้หมดแล้ว)
- ⚠️ ถ้าแก้ worker.js รอบหลัง ให้แก้จากไฟล์ล่าสุดที่มี 4 จุดนี้อยู่ ไม่งั้นแจ้งเตือนจะหยุด

ถอดออก: ลบ 4 จุดที่เพิ่ม + ไฟล์ `oee-push.js` (ตาราง `push_subs`, `push_state` ลบหรือเก็บไว้ก็ได้)
